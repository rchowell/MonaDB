= Select Statement

The select statement is the final projection. It runs once per binding tuple and emits one output value per tuple.

== Syntax

[source,mckeeman]
----
select_stmt
    "select" select_ctor query_body_opt

select_ctor
    "."
    "*"
    expr
    select_list

select_list
    select_item
    select_item "," select_list

select_item
    expr
    expr "as" identifier

query_body_opt
    ""
    query_body

query_body
    from_clause with_clause_opt where_clause_opt group_clause_opt order_clause_opt limit_clause_opt
----

== Constructors

`select .` emits the binding tuple as an object with one entry per binding:

[source,sql]
----
insert into T ({"x": 1, "y": 2});
select . from T as t;
-- output: [{"t": {"x": 1, "y": 2}}]
----

`select *` emits the flat spread of all bindings (equivalent to `select {...}`):

[source,sql]
----
insert into T ({"x": 1, "y": 2});
select * from T as t;
-- output: [{"x": 1, "y": 2}]
----

`select expr` emits a single expression value:

[source,sql]
----
select 1 + 1;
-- output: [2]

select t.x + 1 from T as t;
-- output: [2]
----

`select item, item, ...` emits an object with listed items as members. An item can be:

- `expr as name` — introduce an output key
- `expr` — if a path like `t.x`, the last segment becomes the key

[source,sql]
----
select t.x as a, t.y as b from T as t;
-- output: [{"a": 1, "b": 2}]

select t.x, t.y from T as t;
-- output: [{"x": 1, "y": 2}]

select {"x": t.x, "y": t.y} from T as t;
-- output: [{"x": 1, "y": 2}]
----

== No from clause

With no `from` clause, the query produces exactly one output:

[source,sql]
----
select 1 + 1;
-- output: [2]

select {"a": 1, "b": 2};
-- output: [{"a": 1, "b": 2}]
----
