== Intermediate Representation

* Tree IR is easy to build from the parser.
* Compiler needs to flatten the tree to something more linear for codegen.

* Language is functional-like.
* Parser is tree-like.
* IR is a block tree; where each block makes imperative codegen easier.
* Codegen wants a linear, imperative representation.

[source]
----
// sql like

select map(t) from T as t where predicate(t);

from(T).filter(predicate).map(map);

// functional


// bytecode replicating a fallible streaming iterator

while let Some(value) = T.next()? {  // 0: next(c, n+1)
    if (predicate(value)) {          // .......
        yield map(value);            //
    }
                                     // n: jump(0)
}                                    // n+1


// joins
//-------
// select map(l, r) from L, R where predicate(l, r);
// from (L, R) where, select ...
// from (L, R) | where predicate(l, r) | select map(l, r)

while let Some(lhs) = L.next()? {
    while let Some(rhs) = R.next()? {
        if (predicate(lhs, rhs)) {
            yield map(lhs, rhs);
        }
    }
}

// from (L, R) | select map(l, r)
----

== Deleting Rows

Here is some design for basic row deletions using the MonaDB VM, then invoking SQLite. This may reach a scaling limit (tbd), but it's a start - and I could always batch deletes in an SQLite transaction.

[source]
----
-- input
delete from T where predicate(t);

-- Step 1. execute predicate in MonaDB.
let oids = exec(select oid from T where predicate(t)).collect();

-- Step 2. execute deletions in sqlite.
delete from T where oid in $oids;
----

.Idea
* scan with oid (have locals stack with oid/value pairs)
* each local holds its oid
